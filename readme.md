# QW-Browser API Service

## 项目简介

QW-Browser API 是一个高性能的基于 Python 的浏览器管理与自动化后端服务。它摆脱了传统的 GUI 界面，专注于提供稳定、高效的 RESTful API 接口，支持多浏览器实例的统一管理、控制和大规模自动化任务执行。

本项目特别适合微服务架构、容器化部署以及需要无头 (Headless) 浏览器集群的场景。

## 此版本特性

- **纯后端架构**: 移除所有 GUI 依赖 (PyQt6)，显著降低内存占用和部署体积。
- **标准化接口**: 提供完整的 RESTful API 文档 (Swagger/Redoc)。
- **容器化支持**: 即使开箱即用的 Docker 部署支持。
- **高性能**: 优化的连接池管理、请求去重和智能缓存策略。

## 功能概览

- 📱 **多实例管理**: 统一管理多个浏览器实例（上下文隔离）。
- 🛠️ **全功能 API**: 通过 HTTP 接口控制浏览器行为、页面导航、元素交互等。
- 🔄 **智能重定向**: 支持基于规则、条件的自动页面重定向，并在服务端完成处理。
- � **Cookies 管理**: 统一的 Cookies 管理系统，通过 API 导入/导出/清理。
- 🌐 **网络监听**: 支持监听特定 URL 请求，捕获数据包进行分析。
- 🏷️ **自动化标签**: 自动在浏览器标签页注入用户标识。
- ⚙️ **配置灵活**: 支持通过 API 或配置文件动态调整 Chrome 路径和并发参数。

## 🚀 快速开始

### 1. 环境准备

- Python 3.9+
- Chrome 浏览器（建议最新版）

### 2. 安装依赖

```bash
pip install -e "."
```

### 3. 启动服务

**方式一：直接运行**

```bash
python main.py
# 服务默认监听: http://127.0.0.1:8000
```

**方式二：Docker 运行**

```bash
docker-compose up -d
```

## 核心功能指南

### Chrome 浏览器配置

服务会自动检测系统中的 Chrome。如需自定义，请修改 `conf/chrome_config.json` 或使用 API：

```bash
# 通过 API 设置 Chrome 路径
curl -X POST http://127.0.0.1:8000/api/chrome-config/set-path \
  -H "Content-Type: application/json" \
  -d '{"path": "/path/to/your/chrome"}'
```

### 页面重定向的使用

重定向功能已完全服务化，您可以通过代码或 API 配置规则。

**Python 调用示例**:

```python
from utils.page_redirect_manager import redirect_manager

# 添加规则
redirect_manager.add_rule(RedirectRule(
    source_pattern="example.com",
    target_url="https://new-target.com",
    enabled=True
))
```

### Cookies 管理

为了安全和一致性，由于移除了 GUI，所有 Cookies 操作建议通过 API 进行：

- `GET /api/browser/{user_id}/cookies`: 获取 Cookies
- `POST /api/browser/{user_id}/cookies`: 设置 Cookies
- `DELETE /api/browser/{user_id}/cookies`: 清理 Cookies

## 技术栈

- **API 框架**: FastAPI
- **浏览器自动化**: DrissionPage
- **服务器**: Uvicorn
- **网络请求**: HTTPX (Async)
- **日志**: Loguru
- **部署**: Docker / Docker Compose

## 性能优化

本项目包含多项性能增强：

- **LRU 智能缓存**: 减少重复 I/O 操作。
- **连接池**: 复用浏览器连接，降低握手开销。
- **异步文件 I/O**: 提升高并发下的读写性能。

## 注意事项

1. **Docker 部署**: 容器内运行 Chrome 需要特殊权限，`docker-compose.yml` 已配置基本环境，可能需要根据具体宿主机调整 `--shm-size`。
2. **端口占用**: 默认使用 8000 端口，可在 `main.py` 或环境变量中修改。
3. **数据持久化**: Docker 部署时请挂载 `data/` 目录以保留用户配置和 Cookies。
